# Архив погоды без утечки будущего

Файл `data/weather_forecasts.csv` используется веб-панелью. CLI принимает путь через `--archive`.
Это архив **прогнозов**, а не наблюдений. Формат UTF-8, запятая, десятичная точка:

```csv
turbine,issued_at,available_at,valid_time,wind_speed,temperature,source,kind
1,2026-01-31T06:00:00Z,2026-01-31T12:00:00Z,2026-01-31T19:00:00Z,7.4,2.1,provider/model/run-id,forecast
```

Строка выше — только пример формата, не реальная погода. Для запуска нужны все 24 или 48 часов.

| Поле | Значение |
|---|---|
| `turbine` | 1 или 2 |
| `issued_at` | Инициализация конкретного прогона погодной модели, ISO 8601 с часовым поясом |
| `available_at` | Когда этот прогноз действительно стал доступен пользователю |
| `valid_time` | Начало прогнозируемого часа, с часовым поясом |
| `wind_speed` | м/с, высота должна соответствовать датчику либо быть откалибрована |
| `temperature` | °C |
| `source` | Провайдер, модель, идентификатор запуска для аудита |
| `kind` | `forecast`; `observation`, `reanalysis`, `hindcast` не принимаются |

Алгоритм выбирает самый свежий **полный** запуск для турбины с `issued_at <= origin` и
`available_at <= origin`. Должно выполняться `available_at >= issued_at`. Поздние, неполные,
дублированные и нечисловые прогнозы не используются. Нельзя собрать один горизонт из новых
запусков, появившихся после начала расчёта. SHA-256 исходного архива сохраняется в отчёте.

Достоверность `available_at` и `kind` должна подтверждаться происхождением данных. Проверка
CSV не доказывает, что прогноз реально существовал в прошлом: нужны оригинальные файлы,
сведения провайдера и подтверждение публикации. Не присваивайте задним числом время
доступности реконструкциям.

## Выбор источника для февраля 2026

Текущий Open-Meteo Forecast API подключён для live-режима. Он не используется для февраля.
[Historical Forecast API](https://open-meteo.com/en/docs/historical-forecast-api) склеивает
начальные часы разных прогонов; эта временная серия не заменяет прогноз, доступный на
фиксированный момент расчёта.

[Single Runs API](https://open-meteo.com/en/docs/single-runs-api) позволяет выбирать
инициализацию через `run`. Однако документация указывает, что большинство моделей
архивируется с 2 апреля 2026, а более ранняя история ECMWF IFS HRES представлена
hindcast-реконструкциями. Поэтому этот источник **не подключён автоматически для февраля
2026**: нельзя выдавать реконструкцию за реально опубликованный тогда прогноз.
Время инициализации также не равно времени публикации.

Следующий этап — получить и проверить оперативные архивы на февраль (например, архивы
оригинальных выпусков GFS), сохранить их метаданные публикации и привести к контракту выше.
Пока такого архива нет, февральский бэктест не считается завершённым.
