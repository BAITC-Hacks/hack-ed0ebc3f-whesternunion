# WindPilot — прогноз выработки ВЭС

Локальный MVP команды **WhesternUnion** для HackAlem: две турбины, почасовая нормализованная
мощность на 24–48 часов, подготовка реальных CSV, погодный адаптер, журнал расчёта,
опциональный OpenAI-аналитик и веб-панель.

## Быстрый запуск

Python 3.11–3.13. Проверено на Windows / Python 3.13. Node.js для запуска не нужен.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
.venv\Scripts\python -m uvicorn wind_agent.api:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Интерактивная документация API: `/docs`.
В исходной папке уже есть CSV обеих турбин; проект распознаёт их оригинальные названия.
На другом компьютере положите их в корень или задайте `DATA_DIR` в `.env`.
Код и панель работают без OpenAI-ключа. Если `.env` уже существует, не перезаписывайте его
командой копирования.

## Что работает

- Оригинальные русские столбцы CSV → проверка → средние по полным часам.
- Отдельная HistGradientBoosting-модель мощности для каждой турбины.
- Инерционный baseline без сети и live-погода Open-Meteo по координатам из задания.
- Чтение архива прогнозов с `issued_at`, `available_at` и строгой проверкой отсутствия будущих данных.
- Почасовой replay исторического периода, MAE/RMSE только при наличии фактической мощности.
- JSON с происхождением данных и журналом действий, CSV-экспорт, история запусков.
- Периодический пересчёт `watch`, обнаружение изменения входных данных.
- Опциональный OpenAI-анализ через два function tools, с ограничением количества запросов.

**Февральский бэктест ещё не готов:** нужен проверенный архив погоды, реально опубликованной
на соответствующий момент. Инерционный baseline не выполняет эту часть задания. Подмена
прогноза будущими измерениями, реанализом или hindcast запрещена в контракте архива.

## Данные

Оба переданных файла фактически заканчиваются **31 января 2026**, несмотря на `28.02.2026`
в названиях. Февральской мощности в них нет.

| Турбина | Исходных строк | Пригодных часов | Пропущенных / неполных часов |
|---|---:|---:|---:|
| 1 | 142 360 | 23 728 | 1 664 |
| 2 | 149 499 | 24 919 | 473 |

Наблюдения имеют шаг 10 минут. Требуется минимум 4 валидных уникальных измерения за час;
пустые и недостаточно покрытые часы исключаются, не заполняются будущими значениями.
Мощность должна быть в [0, 1]. Паспортная мощность неизвестна, поэтому МВт/МВт·ч не выводятся.

Допустим и канонический CSV `turbine_1.csv` / `turbine_2.csv`:

```csv
timestamp,wind_speed,power,temperature
2026-01-31 23:00:00,6.7,0.24,1.5
```

Для канонического файла также предполагается 10-минутный шаг. `timestamp` — начало интервала.
Исходные даты без часового пояса интерпретируются в `DATA_TIMEZONE=Etc/GMT-5` (фиксированный
UTC+5). **Это допущение до подтверждения организаторами**, особенно для периода до смены
часового пояса Казахстана. Все внутренние расчёты и графики используют UTC.

## OpenAI

Впишите новый ключ в локальный `.env`:

```dotenv
OPENAI_API_KEY=your-key-here
OPENAI_MODEL=gpt-4.1-mini
```

Перезапустите сервер и отметьте «Добавить OpenAI-анализ». Можно выбрать другую доступную
вам модель с поддержкой Responses API и function calling. Ключ из чата не сохранён в коде;
его следует заменить. `.env`, исходные данные и артефакты исключены из Git.
Проверка OpenAI выполнена через имитацию tool-calling, платные запросы при разработке не
выполнялись. Доступность модели и баланс аккаунта не проверялись.

Интеграция использует [официальный Responses function-calling workflow](https://developers.openai.com/api/docs/guides/function-calling).
Подробности ограничения запросов и передаваемых сводок — в [архитектуре](docs/architecture.md).

## CLI

Команды выполняйте Python из `.venv` (либо активируйте окружение).

```powershell
python -m wind_agent audit --turbine 1
python -m wind_agent forecast --turbine 1 --horizon 48
python -m wind_agent forecast --turbine 2 --mode live --horizon 24
python -m wind_agent forecast --turbine 1 --mode live --ai
python -m wind_agent watch --turbine 1 --mode live --interval 3600
```

Для первого расчёта baseline момент по умолчанию — 1 февраля 2026, 00:00 UTC+5, сразу после
последнего завершённого часа измерений. Он распространяет среднюю погоду последних шести
часов на весь горизонт. Ровная линия baseline — ожидаемое поведение, а не реальная погода.
При отставании последних наблюдений более чем на 6 часов этот режим отказывается работать.

Архивный расчёт и февральский replay:

```powershell
python -m wind_agent forecast --mode archive --archive data/weather_forecasts.csv --origin 2026-02-01T00:00:00+05:00
python -m wind_agent backtest --turbine 1 --archive data/weather_forecasts.csv --start 2026-02-01T00:00:00+05:00 --end 2026-03-01T00:00:00+05:00 --horizon 24
```

`end` не включается. При горизонте 48 часов соседние ежедневные запуски перекрываются:
в CSV сохраняются origin и lead_hour для каждого прогноза, а метрики считаются по всем
парам запуск–час. Если факта нет, `metrics=null`, а не выдуманная оценка качества.
Формат и требования к погоде: [docs/weather-contract.md](docs/weather-contract.md).
В панели архив читается из `data/weather_forecasts.csv` относительно репозитория.

Результаты: `artifacts/runs/*.json`; выгрузка из панели — CSV. Replay дополнительно пишет
`artifacts/backtest-*.json` и `.csv`. Исходные файлы не изменяются.

## Проверки и честная интерпретация метрик

```powershell
python -m pytest -q
```

Тесты проверяют границу времени, неполные часы, запрет будущих наблюдений и погоды,
отказ от реанализа/hindcast, выбор полного архивного запуска, диапазон 0–1, API/CSV,
отсутствие выдуманной оценки без факта и OpenAI tool-calling без сети.

На предоставленных данных хронологическая проверка **модели мощности на измеренной погоде**:

| Турбина | MAE | RMSE |
|---|---:|---:|
| 1 | 0.02155 | 0.04258 |
| 2 | 0.01966 | 0.05105 |

Это не качество прогноза на 24–48 часов и не результат за февраль. Для такой оценки нужен
архив оперативных погодных прогнозов и фактическая мощность тестового периода.
Диапазон вокруг линии учитывает остатки модели мощности, но не погодную неопределённость.
